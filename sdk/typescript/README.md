# worldview-core (TypeScript)

TypeScript SDK for the [worldview-core](../../README.md) format: a portable JSON
representation of a **worldview**, a set of natural-language **statements** connected by
**arguments**, where an argument is a directed hyperedge from N premise statements to M
conclusion statements.

This package is a complete port of the Python reference implementation: validation,
content-derived identity hashing, structural queries, diff, the JSON Schema, and a CLI.
It has **zero runtime dependencies**, is **synchronous** throughout, and runs unchanged in
**Node and browsers** (SHA-256 is implemented in pure TypeScript; the only Node-specific
code is the CLI).

**Hashes are identical to the Python implementation.** Every `prop_id`, `just_id`,
`arg_hash`, and every query and diff result is byte-for-byte the same as
`worldview_core` produces. The repository's conformance suite (`conformance/vectors/`,
generated by `conformance/generate.py` from the Python code) is replayed in full by
`npm test`: primitives (`canon` and `H` pairs), every case file (identities, foundations,
sccs, well-founded lint, and `rests_on` / `supports` at full depth and depth 1 for every
statement), every invalid document, and every diff, all compared with deep equality.

## Install

```
npm install worldview-core
```

Requires Node 18 or newer for the CLI and tests; the library itself needs only ES2022,
`TextEncoder`, and `String.prototype.normalize`.

From this repository:

```
cd sdk/typescript
npm install
npm run build      # -> dist/ (ESM + .d.ts)
npm test           # builds, then replays the conformance vectors and unit tests
```

## API

Everything is exported from the package root. Names are camelCase versions of the Python
API; result objects keep the Python key names (`prop_id`, `co_conclusions`, ...) so the
JSON is interchangeable.

### Parsing and validation

```ts
import { parseWorldview, parseWorldviewJson, validateDict, ValidationError } from "worldview-core";

const wv = parseWorldviewJson(text, "my-worldview.json"); // throws LoadError / ValidationError
const wv2 = parseWorldview(JSON.parse(text));             // same, from parsed data

const problems = validateDict(raw); // string[]; empty means valid
try {
  parseWorldview(raw);
} catch (e) {
  if (e instanceof ValidationError) console.log(e.problems);
}
```

- `validateDict(data: unknown): string[]` mirrors the Python validator: structural checks
  that match the JSON Schema exactly plus referential integrity (unique ids, every
  reference resolves). Cycles are never a problem.
- `parseWorldview(data: unknown, source?: string): Worldview` validates and builds.
- `parseWorldviewJson(text: string, source?: string): Worldview` also parses JSON text.
- `worldviewFromDict(doc, source?)` builds without validating; `worldviewToDict(wv)` gives
  back the file form (round-trips exactly). `meta` and `ext` are carried through untouched.
- `getStatement(wv, id)`, `getArgument(wv, id)` (throw `UnknownIdError`), `statementIds(wv)`,
  `argumentIds(wv)`.

`Worldview`, `Statement`, and `Argument` are plain object types mirroring the JSON:

```ts
interface Statement { id: string; text: string; mode: "is" | "ought"; meta?: JsonObject; ext?: JsonObject }
interface Argument  { id: string; premises: string[]; conclusions: string[]; justification: string;
                      rule?: string; meta?: JsonObject; ext?: JsonObject }
interface Worldview { version: string; name?: string; description?: string; meta?: JsonObject; ext?: JsonObject;
                      statements: Statement[]; arguments: Argument[]; source?: string }
```

### Identity

```ts
import { computeIdentities } from "worldview-core";

const ids = computeIdentities(wv);
ids.propId.get("walk-commute");   // 64-hex proposition id
ids.justId.get("walk-commute");   // 64-hex justified-statement id
ids.argHash.get("walk-for-health");
ids.sccOf("habit-reports");       // ["self-knowledge", "habit-reports"] or null
ids.toDict();                     // { statements: [{ id, prop_id, just_id, scc? }], arguments: [{ id, arg_hash }] }
```

The primitives are exported too: `canon(text)`, `H(...parts)` (each part a string or a
string array), `propId(text, mode)`, `WHITESPACE`, and `sha256Hex(bytesOrString)`.

### Queries

Each returns plain data, identical in shape and order to the Python functions and to the
CLI's `--json` output.

```ts
import { foundations, sccs, restsOn, supports, wellFounded } from "worldview-core";

foundations(wv);                     // [{ id, text, mode }]
sccs(wv);                            // [{ members, self_loops, internal_arguments, boundary_arguments }]
restsOn(wv, "need-raincoat");        // { statement, text, direction: "up", closure, sccs, tree }
restsOn(wv, "need-raincoat", 2);     // depth limit: cut-off nodes carry truncated: true
supports(wv, "walk-commute");        // direction "down": co_premises + conclusions per argument
wellFounded(wv);                     // { foundations, grounded, ungrounded }
```

In a closure `tree`, each statement is expanded once; a later encounter is a leaf with
`seen: true`. Nodes inside a cycle carry `scc: [...]`. Unknown ids throw `UnknownIdError`.

### Diff

```ts
import { diff } from "worldview-core";

const d = diff(a, b);
d.statements.identical;    // [{ a, b, just_id }]
d.statements.rejustified;  // [{ a, b, prop_id, text }]
d.statements.added;        // [{ id, text, mode }]  (in b only)
d.statements.removed;      // (in a only)
d.arguments.identical;     // [{ a, b, arg_hash }], plus added / removed
d.summary;                 // counts
```

### Graph

`Graph.build(wv)` exposes `incoming` / `outgoing` (statement id to argument ids),
`succ` / `pred` (statement adjacency), `foundations()`, `sccs()` (topological order, same
member order as Python), `sccOf()`, `isCyclicComponent(comp)`, `cyclicSccs()`,
`upstream(id)`, `downstream(id)`. Every query accepts an optional pre-built `Graph` as its
last argument.

### Schema

```ts
import { schema } from "worldview-core"; // the JSON Schema (draft 2020-12) as a plain object
```

Identical in content to `src/worldview_core/worldview-core.schema.json`; regenerate with
`npm run sync-schema` if the schema changes.

## Command line

`bin/worldview.js` mirrors the Python CLI. After `npm install -g worldview-core` (or from
this directory, `node bin/worldview.js` after building):

```
worldview [--json] <command> ...

  validate <file> [--jsonschema]
  ids <file>
  rests-on <file> <id> [--depth N]
  supports <file> <id> [--depth N]
  foundations <file>
  sccs <file>
  lint well-founded <file>
  diff <a> <b>
  schema
```

`--json` emits exactly the data the library returns (the same as the Python CLI's `--json`).
Exit codes: 0 success, 1 the file is not a valid worldview (or cannot be read), 2 usage
error or unknown id. `--jsonschema` is accepted for parity with the Python CLI but only
prints a warning: the built-in validator already mirrors the schema exactly, and this
package has no JSON Schema dependency.

```
$ worldview rests-on examples/walking-to-work.json need-raincoat
need-raincoat: I should own a good raincoat.
  <- raincoat
      walk-commute: I should walk to work.
        <- walk-for-health [practical syllogism]
            exercise-good: Regular physical activity improves long-term health.  [foundation]
            ...
```

## Development

```
npm run build       # tsc -> dist/
npm run typecheck   # type-check src and tests without emitting
npm test            # build + vitest (conformance replay, SHA-256, API, CLI)
npm run clean       # remove dist/
npm run sync-schema # regenerate src/schema.ts from the Python package's schema
npm run fuzz        # cross-language fuzz against the Python reference (needs the repo's .venv)
```

Layout mirrors the Python modules: `src/canon.ts`, `src/sha256.ts`, `src/model.ts`,
`src/validate.ts`, `src/graph.ts`, `src/identity.ts`, `src/queries.ts`, `src/diff.ts`,
`src/schema.ts`, `src/cli.ts`, `src/index.ts`.

### Fuzzing against the Python reference

`npm test` is self-contained (it replays the checked-in conformance vectors). `npm run
fuzz` goes further: `scripts/fuzz.mjs` generates random worldviews of many shapes (dense
cycles, self-loops, zero-premise arguments, joint conclusions, unicode text in every
normalization form, ids such as `__proto__`, nested `meta`/`ext`), runs each through this
SDK and through the Python implementation (`scripts/fuzz-reference.py`, on the repository's
`.venv`), and compares with deep equality: validity, every hash, the full SCC order,
foundations, sccs, the well-founded lint, `rests_on`/`supports` for every statement at
several depths, and diffs in both directions against a mutated copy. A hand-built corpus of
edge shapes runs first, random text and part lists go through `canon`/`H`, corrupted
documents through both validators, and on a sample of graphs the two CLIs' stdout is
compared byte for byte. `--count`, `--seed`, `--cli`, `--python`, and `--out` (where
failing inputs are written) are documented at the top of the script.

Two known, deliberate non-goals of the comparison: Python's hand-written validator accepts
an `id` or `version` with a trailing newline (its `$` anchor matches before a final `\n`),
which the JSON Schema and this SDK reject; and NFC of characters assigned after the Unicode
version that the local Python was built with (15.1 for Python 3.13, against 17.0 in Node
24) can differ in canonical reordering. The fuzzer avoids both.
